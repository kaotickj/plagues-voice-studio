# Agent instructions

## Mandatory incremental reporting and continuity

Reporting is part of execution, not an optional end-of-session activity. Never wait for an owner reminder. These instructions apply to local, remote, delegated and owner-executed-script work.

Before substantive work, verify repository identity, authorized branch, current revision, scope, applicable reporting destinations and outstanding obligations. Read the root handoff.md and applicable project procedures.

After each meaningful increment, including failed tests, interrupted experiments, technical discoveries, decisions and blockers:

1. Verify the actual outcome and preserve primary evidence.
2. Record exact commands, revisions, configurations, hashes, results, limitations and next actions as applicable.
3. Update the root handoff.md with publication-safe continuity information and update AGENTS.md for durable technical discoveries.
4. Maintain applicable private continuity records and research dossier; submit research evidence through the authorized private coordination process.
5. Record application and academic synchronization dispositions and publication disposition. Verify receipts before claiming integration.
6. Establish the next actionable checkpoint before advancing dependent work.

The directing agent remains responsible when the owner executes commands. Scripts should produce durable evidence and failure receipts where practical. Conversation summaries, proposed updates and unverified submissions do not constitute completed reporting.

If blocked, preserve evidence immediately, identify the outstanding requirement, reason, responsible party and next corrective action. Do not claim full synchronization or advance dependent work with undocumented results.

This is a public application repository. Keep unpublished research findings, private paths, credentials, recordings, protected validation data and other restricted material outside public Git history. Record only publication-safe engineering information here. Private synchronization does not authorize publication, deployment or visibility changes. Respect existing repository and release boundaries; never force-push or discard unrelated work.

Execute. Verify. Preserve. Document. Synchronize. Continue.

## Mandatory end-of-run report attachment (2026-11-27)

Every experimental, qualification or meaningful research execution must include its reporting stage in the same runner or invocation, including failed or interrupted runs wherever technically possible. Register the assignment and execution ID before execution; capture exact commands, source revision, model/runtime configuration, input/output hashes, result and diagnostics incrementally. At finalization, preserve a durable receipt and a concise, disclosure-reviewed report, update applicable handoff/dossier/continuity records, and submit through the authorized research coordinator. Use the existing local submission mechanism when available, run the coordinator, and recover the exact job's verified receipt (including when a timer already processed it). Do not print an unrelated latest commit or a preceding experiment's commit as the current report.

Attach the report summary automatically at the end of the terminal run and save the same summary beside the execution evidence. Include execution ID, result, evidence location, research job key, source/application commit IDs, immutable submission commit if applicable, academic integration commit, verification status and any outstanding reporting leg. Print actual verified identifiers; if synchronization is blocked, explicitly print the error/pending status and recovery action. A local execution receipt alone is insufficient. For direct local intake there is no separate remote submission-branch commit. The goal is that an authorized remote agent can retrieve the current report from its exact academic commit without requiring the owner to locate or paste raw logs. A compact report must contain sufficient approved evidence to review the actual run; preserve restricted primary artifacts privately and identify any access limitation. Never expose private repository identifiers, unpublished results, credentials, private paths, or restricted material in public Git history or public output. Failed reporting must not trigger repeated inference when saved evidence suffices. Recover existing evidence first; repeat only unverifiable work under a new execution ID with reporting enforced. Do not claim technical enforcement until actually implemented and verified.
